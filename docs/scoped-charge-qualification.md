# Whole-scope charge qualification: advisory, read only

This planner inventories the agreed active managed England-and-Wales CCOD title subset selected by recorded price paid above GBP 5 million, not current value. It does not assume the earlier audit's counts remain current. Source traversal uses keyset pages within one REPEATABLE READ READ ONLY transaction. Missing proprietor rows, missing/invalid candidate numbers and outdated source membership remain visible. Titles, source rows (including missing-proprietor placeholders), actual proprietor records, candidate companies and approved target companies are separate counts.

The reader performs SELECTs only, never calls the locking review helpers, and creates no schema, proposal, event, scan, mapping or permission. A wholly absent review store yields an inventory with no ready entries; a partial store is an explicit error. Cached profile-name consistency produces review_required_profile_consistent, never approval. This is not automatic identity verification or an approved bulk-review policy.

Existing proposals are evaluated with the actual identity policy, original source binding, profile/evidence freshness, newest events, reviewer-enabled/scan-authority flags and approval expiry. Consumed scan events are not reused. Conflicting approved targets remain held even if one permission was consumed. One valid source may justify collecting one company's charges, but its approval is never transferred to another proprietor row. Deduplication applies to company collection, not ownership claims.

Ready company references are split into manifests of at most 100 entries without truncating the dataset. These are advisory references, not execution authority or API budgets. The existing staging worker must freshly re-authorize them. scan_permission_used means a permission was consumed, not current successful coverage. This build does not reconcile all failed/checked/published states or implement a persistent queue or search publication.

The CLI scripts/plan_scoped_charge_batches.mjs requires --output and guarded CCOD_TEST_DATABASE_URL. It writes the report with mode 0600, refuses to overwrite an existing file, and logs summary counts rather than raw source/profile data. It has no --apply option or API client. --batch-size controls chunk size, --page-size controls database read pages; neither is a total-result cap. It has not been run against Neon.

Local scope tests use a formatting-normalised copy of the retrieved policy and simulated SQL. The synthetic 15,005-title/4,001-ready-company case verifies complete accounting and 41 batches; these are test counts, not real dataset measurements. Real PostgreSQL planner tests are prepared for CI and must pass before claiming SQL validation. Test order is existing staging fixtures, batch fixtures, then planner fixtures; only the disposable planner tests drop review tables to exercise absent-schema behavior. No live grants, approvals, collection, retries, publication, schedule or merge are authorised. Base: PR #16 head 1c7179f.
